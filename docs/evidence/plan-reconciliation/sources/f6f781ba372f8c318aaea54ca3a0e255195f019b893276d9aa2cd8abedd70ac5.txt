## Finding

Observed:

1. **#189 merged at 99ea45f.** The host python-qiskit-aer-cuda 0.17.2-2 links libcustatevec.so.1 and libcutensornet.so.2 (readelf NEEDED). `noise_simulator(custatevec=True)` reports `cuStateVec_enable` true.
2. **G1 is reconciled with main and #189.**
   - noise_simulator batches GPU shots by default up to 10 active qubits. Feed-forward circuits run unbatched (SnapshotSimulator.run), and shot branching is never enabled.
   - `custatevec=True` turns the batched default off.
   - G1 adds `GOROROBA_AER_CUSTATEVEC=1` (calibration_snapshot.aer_custatevec), so an entry that takes its device from aer_device() runs on libcustatevec.
   - Measured on the 4070 Ti: cuStateVec engages on density_matrix as well as statevector, with seeded counts equal to the plain GPU path at 8, 12 and 14 qubits.
   - core-367, core-279 and the seeded-count CPU gates pass.
3. **T4 probe returned no rows.** Kaggle kernel gororoba-aer-gpu-config, version 1, pushed at befa671 with `--timeout 5400`, reached CANCEL_ACKNOWLEDGED at the timeout (10:08Z). It returned environment.json, hypercomplex.json and pip.txt: cuquantum-cu11 24.8.0, custatevec-cu11 1.6.0.post1 and cutensor-cu11 2.2.0 installed, driver CUDA 13.0. It returned no probe row.
   - Cause (kaggle_kernel/kernel_main.py run_entry): the kernel runs the entry with `capture_output=True` and copies changed repository files only after the entry exits. A kernel cut off at `--timeout` therefore loses the entry's stdout and its `--out` file under the repository copy.
   - Cost: the host probe spent 2,862 s inside rows on 12 CPUs. The T4 host has 4 CPUs, so the probe's contention rule reruns rows whose load exceeds 4, and its 30 s idle wait applies to each of 74 rows. That overran 5400 s.
   - 1.5 h of GPU quota went with no data.
4. **#68 ghost estimator on GPU** (sim/ghost-branching-gpu merged with G1):
   - core-363 passed in 35.7 s and core-364 in 4.1 s.
   - `--runs all --engine torch --device cuda --dtype complex128` took 58.7 s wall for 15 runs (1 skipped), all 50 grid points each. Phases summed: prepare 10.6 s, export 41.4 s, evolve 1.3 s, sample 1.1 s. Export runs in the CPU pool, so it is the bound.
   - One Aer grid point (run 2026-10-11T152922, 29 replicas of 2 to 6 active qubits, 118,784 shots, density matrix):

     | Configuration | Seconds | Mean TVD at (1, 1) |
     |---|---|---|
     | CPU, 12 threads | 70.5 | 0.10227 |
     | GPU + cuStateVec | 501.8 (7.1x slower) | 0.10227 (equal) |

   - Narrow dynamic circuits run one shot at a time on the GPU executor, so Aer on the GPU loses here. The GPU gain on this workload comes from torch exact branching.
5. **Kaggle's GPU Aer.** qiskit-aer-gpu-cu11 0.17.2 is the only GPU wheel that installs on the image's Python 3.13. It is built against CUDA 11.8, while the T4 image's driver reports CUDA 13.0 and its torch is 2.11.0+cu128 (docs/notes/kaggle/substrates.md).

Inferred, not measured: an Aer 0.17.2 wheel built from the host recipe (docs/notes/build_host/recipes/) as cu13, for sm_75 plus sm_89, would run on the T4 under CUDA minor-version compatibility. It would also load libcustatevec through a cuquantum cu13 wheel (custatevec-cu13 1.15.0 is on PyPI).

2. **#68 benchmark (sim/ghost-branching-gpu, rebased by merge onto main after G1).** Retain docs/evidence/ghost_error_scale_branching/gpu_benchmark.json. It holds:
   - the torch CUDA complex128 run over all runs, plus complex64 as a separate row only if its laws agree with complex128 within 1e-6 TV;

## Acceptance and falsifier

- **G1.**
  - Prediction: the T4 `gpu_statevector_custatevec` rows report `cuStateVec_enable` true, with `tvd_to_cpu_statevector` inside `sampling_scale`.
  - Falsifier: a `failed` row whose stderr_tail reads "does not support cuStateVec". The cu11 wheel's library then did not load.
  - The batched default must beat unbatched at 7 and 10 static qubits on the T4, as on the host. A T4 ratio below 1 at 7 qubits would make the default wrong for Kaggle.
- **#68.**
  - Prediction: torch CUDA and numpy laws agree within 1e-10 at complex128. The GPU wall time stays export-bound, with export above 50 percent of wall.
  - Falsifier: a law difference above 1e-8, or a best (c, r) that differs from the Aer parts.
- **cu13 wheel.**
  - Prediction: it imports on the T4 and reports `cuStateVec_enable` true. Its seeded GPU counts equal the cu11 wheel's for statevector without cuStateVec.
  - Falsifier: an import or `CUDA driver version is insufficient` failure on the 13.0 driver. That would rule out a 13.4-built wheel, and the build would move to a CUDA 12.x toolchain.
