## Check 2: independent Statevector check

Scratch script check2_statevector.py (session scratchpad, not in the repo). Laws come from qiskit Statevector amplitudes with explicit little-endian indexing, not from partial_trace or kron. C comes from amplitudes as sum over b0 of (-1)^b0 times sum over spectator s of psi[b0, wa=0, s, wb=1] * conj(psi[b0, wa=1, s, wb=0]), which is rho_{01,10} in |work_a work_b> order.

- immediate, settings xx/xy/yx/yy, window 836: C = 0.5 + 0j, |C| = 0.500000000000, arg = 0. Difference from the amplitude value: 1.1e-16.
- matched_idle: |C| = 0.5, difference 1.1e-16. measure_reset: |C| = 0.5, difference 2.2e-16.
- All 15 independent laws agree with coherence_window._expected_law to 1.1e-16, and with the 15 table rows of UNAPPROVED_CASE.md:48-62 to 2.2e-16.
- RZ(+0.3) on work_b: arg(C'/C) = +0.300000. On work_a: -0.300000. |C'|/|C| = 1. The +delta on work_b, -delta on work_a convention holds.

Analytic cross-check. After the prefix, the state is (|0>_c (|10> + |01>) + |1>_c (|10> - |01>)) / 2 up to the control's Hadamard, so branch b0 carries (|10> + (-1)^b0 |01>)/sqrt(2) with weight 1/2. Then S_XX = S_YY = 1, S_XY = S_YX = 0, and C = 1/2. The circuit has no phase gate, so the ideal phi is 0. The case's phi is a hardware quantity that the code never parameterizes.

Round-1 prefix. It matches qpe_diagnostics.n21_orbit_diagnostic gate for gate (qpe_diagnostics.py:193-197: x(one), h(0), cswap(0, one, four), cswap(0, four, sixteen), h(0)). The mapping one=WORK_A, four=SPECTATOR, sixteen=WORK_B follows the compose map in patch_characterization.orbit.

## Check 4: case statements against code and record

Contradicted:

C1. UNAPPROVED_CASE.md:36 says a static detuning above 150 kHz aliases. The window is 836 dt x 4 ns = 3.344 us, and aliasing begins at 1/(2T) = 149.52 kHz. A 149.8 kHz detuning aliases, but the sentence's rule ("converts ... only below that bound") would admit it. Correct value: about 149.5 kHz. SLOPPY.

C2. QPU_OPTIMIZATION.md:158 says qpe_diagnostics.py "derives both families' laws independently of Qiskit using exact integer branch amplitudes and rational probabilities". For the coherence family, the law path is coherence_window._expected_law (coherence_window.py:125-128), which calls qpe_diagnostics.ideal_branch_probabilities (qpe_diagnostics.py:315-327). That function builds qiskit.quantum_info.Statevector float states (import at qpe_diagnostics.py:21; IdealBranch = tuple[float, Statevector, int] at :32). The claim does not hold for the coherence family. Confidence about 80 percent that "both families" includes it; the doc does not name the families.

Consistent, but scope omitted:

O1. UNAPPROVED_CASE.md:36 says that in the immediate and matched-idle contexts "correlated readout crosstalk enters C as a context-independent scale". That holds for those two contexts: all four measurements sit in one final layer (coherence_window.py:93-96), and the static ISA circuits show it. The sentence is silent on measure_reset, where b0 is measured mid-circuit before the window (coherence_window.py:84-87) and read in a different layer from the work pair. The measure_reset comparison carries the rotation and shrink test, so its readout scale is uncharacterized. SERIOUS for interpretation.

O2. UNAPPROVED_CASE.md:34 and QPU_OPTIMIZATION.md:145-147 say rotation and shrinkage "separate the explanations". A coherent control-work interaction during the window is not on the list. A branch-dependent phase exp(-i theta Z_c Z_wb) during the matched idle gives C'/C = cos(2 theta), which is real: a pure shrink with no rotation. Verified numerically (scratch zz_probe.py): theta = 0.1 gives 0.980066578 = cos(0.2); theta = 0.3 gives 0.825335615 = cos(0.6). Under the case's classification this is indistinguishable from dephasing. The ISA prefix has cz pairs (142,143), (136,143), (143,144) and no control-work cz, so a direct control-work edge is not evidenced; the coupling map is not in the record, so its absence is not established. measure_reset has no superposed control during its window, so the effect enters the matched-idle comparison and propagates to the measure_reset comparison. SERIOUS for interpretation; not a code defect.

O3. UNAPPROVED_CASE.md:192 says every PUB cost includes "declared reset/classical-latency additions". That is literally true. The classical-latency term is sequential_stage_count x --classical-latency-us (qpu_planning.py:614-618), and all 15 PUBs in record.json have sequential_stage_count 0, so the 20 us controller latency adds 0 s. The case's table shows 0, but the text should state why, since the flag appears in the command. SLOPPY.
