# PR #184: live_run: record backend_version and processor_type in every run record

Owner session: ibmquantum-12 (adopted from a closed session). Branch: records/backend-identity-in-run-records (head 79ce8e1, 19 files, +328/-23).

## Finding

The PR records backend identity (backend_version, processor_type from
`backend.configuration()`) as data in run records, collect.json, snapshots,
simulation records and Kaggle submissions, outside the approval comparison.
Codex round 1 is complete (summary head 79ce8e1) with three open P2 threads,
read in full with `scripts/codex_review_status.sh 184`:

1. live_run.py:4615 -- a job whose `job.result()` raises (ERROR, CANCELLED)
   is checkpointed before the identity assignment, so its collect.json entry
   lacks backend_version and processor_type.
2. live_run.py:3123 -- an identity-only change between planning and submit
   leaves `unchanged_since_planning` true, so the submitted record keeps the
   planning-time identity in `backends`, `system_inventory` and group
   entries.
3. scripts/kaggle_run.py:430 -- `build_shard_kernel` writes
   `kaggle-ci-shard-v1` submissions without `aer_device` or snapshot
   identity.

The PR body lists contracts not run locally: correction_planning_contracts,

## Reachability

All three threads are reachable through documented interfaces: `--collect`
on a failed or cancelled job (1), an approved `--submit` after a backend
version bump (2), `kaggle_run.py shards` (3). Each gets a fix.

## Design

Merge main into the branch first (main moved past 06:04Z, several merges).
Then: (1) initialize the configuration identity when `job_out` is created
and augment with execution-start versions when timing exists; (2) keep
identity out of the approval comparison but copy the fresh identity into
the record's provenance fields before submission on both the reselected and
unchanged paths; (3) add the same fields to the shard submission path and
its self-test. Contract additions in runtime_contracts.py for (1) and (2).
Gates: existing ones; a new one only if a new check script appears
(core-497).
