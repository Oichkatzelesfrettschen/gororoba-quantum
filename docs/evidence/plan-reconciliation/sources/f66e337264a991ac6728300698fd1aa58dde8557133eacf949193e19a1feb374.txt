## Reachability

Reached through a CI lane: any pull request that edits proofs/,
docs/evidence/{c881_exhaustive,formal_certificates,folding_proofs,stiefel_witness},
the pin file or the replay script. A proof edit that no longer compiles under
Rocq 9.2, or a receipt edited without regenerating the compiler output,
passes every current gate: the pr tier checks receipt bytes and sha256 ledgers
(sources suite, gates.json:1503-1519) and never invokes the compiler. The
manual AGENTS.md replay is the only defense, and it is a human step. Severity:
medium for proof-bearing PRs, none for the other changes.

## Design

Decision: one path-filtered job `rocq-replay`, outside the gate shards, using
opam with a pinned switch and an actions cache, calling
scripts/rocq_kaggle_replay.py in a new mode. Rocq 9.2 on OCaml 5.5.0 is the
only toolchain the four bundles and the receipts were derived under.

Install routes compared.
1. Official image rocq/rocq-prover at a pinned digest: pull is fast (about 1
   min, inferred) and the digest pins exactly, but the image compiles with OCaml
   4.14.2 and ships rocq-stdlib 9.1.0. `rocq --version` would print
   "compiled with OCaml 4.14.2", so all four replay scripts exit 1 at their
   version check (c881 line 13). Moving to it means rewriting four
   toolchain.txt files and four SHA256SUMS and re-deriving every receipt
   under a different compiler and stdlib. Rejected.
2. opam on the runner with ocaml/setup-ocaml (action pinned by commit sha) and
   an actions/cache of the switch: builds the same artifact the Kaggle runs
   retained (ocaml-base-compiler.5.5.0, rocq-runtime/core/stdlib 9.2.0).
   Cold about 14-15 min (324 s + 543 s measured on a Kaggle CPU kernel; a
   GitHub runner is inferred to be within a factor of 1.5); warm restore
   about 1-2 min (inferred; the switch size is not measured). Chosen. Pinning:
   action sha, compiler 5.5.0, the three Rocq packages at 9.2.0, and the
   opam-repository commit (setup-ocaml `opam-repositories` input) recorded in
   `ci/rocq_opam_repository.pin`, chosen at implementation as the commit the
   first cold build resolves, with `opam list --installed` printed into the
   job log and uploaded. `rocq --version` against toolchain.txt is the final
   authority and the scripts enforce it.
3. Own image built once from the rocq_kaggle_replay.py recipe, pushed to GHCR
   and pulled by digest: about 1 min per run, exact pin, but adds an
   out-of-tree artifact, a build workflow and registry permissions. Listed as
   a follow-up if the warm opam job proves too slow.
4. Build from source each run without cache: 15 min on every filtered PR.
   Rejected.

Bundles covered, one job: formal_certificates, c881_exhaustive, folding_proofs,
stiefel_witness, TargetFlipN21. folding_proofs, c881 and Stiefel bind
open_gororoba bytes; commit 7d95d228db6be8a5b2f613430f04f2385d6ae48a satisfies
all of them (observed: folding hashes 0 of 22 bad at 7d95d228 and 1 bad at

crates/algebra_experimental/src/sedenion_subalgebras,
crates/cd_kernel/src/cayley_dickson (the directories source_hashes.sha256 of

Reporting in the shard model. `rocq-replay` is a separate job, not a
gates.json entry: run_gates.py shards run on the python pin stack with a
longest-first assignment of measured seconds, and a 15-min toolchain install
plus 13-min replay would unbalance every shard. The job name appears as its
own check on the PR. A gates.json entry with a new tier ("proof") would need
run_gates.py tier plumbing, an opam environment on every shard runner or a
dedicated shard, and a conditional that run_gates.py does not model; rejected
as larger and weaker.

Path filter and required checks. Main is unprotected (observed: branch
protection 404), so no check is required today and a skipped job blocks
nothing. The design still filters at job level (`if:` on a job) instead of
workflow level (`on.pull_request.paths`): a workflow-level filter leaves a
required check "Pending" forever on unrelated PRs if protection is ever
enabled, while a skipped job reports success. The `changes` job always runs
and is the only candidate for a required check. AGENTS.md's merge rule
("every shard is green and threads resolved") gains "and the rocq-replay job
when it ran".

Wall time on a filtered PR: warm about 1-2 min restore + 13 min replays
(Stiefel 541 s dominates) = about 15 min; cold about 28 min; nightly
schedule runs it every night to keep the cache alive (actions caches expire
after 7 days without access) and to catch toolchain drift.

Falsifiers. (a) The first cold run fails the version check: the opam
solver resolved a Rocq that prints a different banner; pin opam-repository
at the commit the Kaggle result used and compare `opam list`. (b) A replay fails
on GitHub's runner that passed on Kaggle: receipt bytes are
host-dependent, which is a finding to record and not to paper over. (c) Cache
restore exceeds 5 min or the switch exceeds the 10 GB cache budget: fall back to
route 3. (d) Mutation check: append a Lemma with a `Admitted.` to
proofs/FoldAverageDescent.v on a scratch branch; the job must go red at
formal_certificates.
