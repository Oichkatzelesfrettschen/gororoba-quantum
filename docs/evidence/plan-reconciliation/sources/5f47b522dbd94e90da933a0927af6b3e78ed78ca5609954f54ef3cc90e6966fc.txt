## Shard count (simulation over ci/gate_timings.json, 4 slots per shard)

max shard wall: 6 -> 610 s, 8 -> 537, 10 -> 566, 12 -> 468, 14/16 -> 468 (core-597 floor). Chose 12.
With ~40 s cached setup a full-selection shard is ~508 s, above the 8 min target; ledger skips reduce the
selected set. 12 shards + changes, qi-stack, ubuntu-24, external-ground-truth, rocq = 17 of 20 free-plan
concurrent jobs, so a second concurrent run queues. CI wall and setup times: not run (no push).

## Floor

- core-597 (468 s on 4 workers): `ghost_run.replay_all_pairs` already maps independent pairs through
  `parallel.ordered_map`; an item-range argument (`--pairs i/N`) registered as case gates would split it
  across shards without changing the replay.
- core-513 (445 s, single thread): `static_self_test` draws all three truths from one generator first,
  then runs three independent `static_cross_validation` fits plus the S3 record; those four items (and
  the four folds inside each) can go through `parallel.ordered_map` or become case gates that redraw the
  inputs and fit one truth. Not changed.

## Limits

- os.stat / exists / is_file, clock reads and C-extension file opens raise no audit event; only the
  nightly `--ledger-audit` catches a gate that depends on them.
- Content digests are memoized per runner invocation; an untraceable gate rewriting a repo file while a
  traced gate runs can stale a digest.
- qi-stack job does not use the ledger.
- docs/local/ is git-ignored, so this report is not committed.
