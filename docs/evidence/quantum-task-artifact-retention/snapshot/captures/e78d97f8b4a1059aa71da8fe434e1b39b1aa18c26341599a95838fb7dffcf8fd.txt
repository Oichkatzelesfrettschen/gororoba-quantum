# Numerical replay runtime and comparator audit

The audit reads retained acquisition records, admitted analysis reports, source history, current checker branches and runtime configuration. The audit executes metadata/native-library probes only; it executes zero fits and changes zero archived reports. Parent-owned native replay processes remain independent of this review.

## Observed numerical runtime

All five underlying acquisition records (2026-10-19T151959.226467Z, 2026-10-19T231043.083602Z, 2026-10-20T031212.175942Z, 2026-10-21T043156.858484Z and 2026-10-21T064222.721454Z) record NumPy 2.5.4, SciPy 1.18.1 and Qiskit 2.5.2 in record.json versions. Both requirements.txt and ci/requirements-replay.txt retain the same NumPy/SciPy versions. Requirements at the report-admission commits also retain those numerical versions. The numerical failures therefore do not establish a NumPy/SciPy release-version mismatch.

The native probe explicitly bounded BLAS/OpenMP threads to one. The parent's separately retained native-numerical-runtime.json is its own fingerprint; its captured OpenMP thread count differs, so the two probes are not silently treated as an identical thread configuration.

Pacman records place Python 3.14.8 installation on 18 October, NumPy installation on 11 October, SciPy installation on 24 August and AOCL installation on 12 June 2026. Those installations precede the acquisitions. docs/notes/build_host/python-stack.md records AOCL as the host BLAS/LAPACK provider. These observations identify a strong native runtime candidate. The admitted numerical reports omit per-analysis compiler, Python patch version, native-library hashes, CPU dispatch and thread fingerprints. Their acquisition records establish package observations at acquisition, not a complete runtime identity for every later analysis. An exact historical numerical environment remains uncertified.

The data support a numerical-build boundary, not a unique attribution to AOCL, OpenBLAS or a specific optimizer defect. The test does not establish a globally optimal fit or reproduce the other six gates. The native bundle remains a candidate historical numerical substrate until its per-report reproduction and complete runtime identity are independently qualified.

## Source admission and bounded closure route

The retained Ramsey report's two-file analyzer closure matches the inspected feature sources exactly. The two retained segmented reports bind 63 source files; their differing paths are qpu_planning.py and n21_q143_segmented_sweep.py. Source history since admission shows an explicit resolver-directory provenance change and the new --against comparison interface; the inspected differences do not change the fitting algorithm. The beat report and prospective design table lack a complete per-analysis runtime receipt. The beat report explicitly labels its models descriptive and post hoc.

All seven gates currently run in the canonical runtime. ci/pins.py registers only the qiskit-2.5 historical profile and validates distribution versions through importlib.metadata. Its existing replay venv remains OpenBLAS-based. Retagging a numerical gate with that profile alone would not recover the native AOCL substrate. ci/run_gates.py returns 127 when a registered runtime lacks its interpreter; ci/premerge_gates.py requires resolution under strict pins. The hosted workflow provisions the historical profile by installing Python wheels. These mechanisms do not currently express an optional native AOCL replay with binary/CPU qualification.

Complete the parent's bounded native probes using unchanged checker comparisons. Retain each exit code, source/data identities and actual runtime/thread/native-library fingerprint beside the gate outcome. Label successful results native-candidate historical report replay, while retaining the canonical OpenBLAS failure as a separate portability residual. Do not report native success as a canonical/hosted pass. Before registering a future native profile, specify and verify the interpreter and extension bytes, BLAS/LAPACK libraries, CPU dispatch, worker/thread settings and immutable input/source identities. Keep portable retained-byte/provenance verification distinct from conditional native numerical reproduction; absence of a native runtime cannot count as a numerical replay. This audit implements no runtime profile and changes no gate requirements.

The separate [review of proposed numerical amendments](retained-log-inputs/proposed-numerical-amendments-review.txt) establishes that the owner's dirty optimization proposals include materially changed alias inference and prospective design choices. Those changes require immutable successors, explicit scientific amendments, optimizer controls and downstream claim review. Neither a wider replay tolerance nor a Qiskit version relabeling justifies adopting them.
