## Statements

- [P] Abstract (p. 1): a block-encoding framework that treats index mapping with coherent permutation as the central mechanism for shift, delete and insert operations, reduces multicontrolled-X control complexity by structured compression, assigns control states under hardware-connectivity constraints through a combinatorial optimization, and supports entry-wise block encoding of general sparse matrices; resource analysis on IBM superconducting backends reports reduced circuit depth.
- [P] Definition (Eq. 4, p. 2): (<0|_anc (x) <i|) U_A (|0>_anc (x) |j>) = A_ij / alpha, with alpha a subnormalization factor.
- [P] Introduction (p. 2): existing sparse block-encoding constructions generally use alpha larger than the spectral norm ||A||_2; whether alpha = ||A||_2 is reachable is stated as open.
- [P] Hamming-distance notation (Eq. 3) is used to organize control states, which suggests the XOR-pair structure of index maps; the paper's matrices are general sparse matrices, not signed permutations specifically.

## Mapping to this repository

- [I] A signed permutation matrix has one nonzero entry per column, so the index-mapping oracle is the entire block encoding; the XOR index map k -> k XOR m of L_{e_m} is the simplest member of the paper's class and its Hamming-distance structure (a fixed bit-flip mask) needs only X gates, with no multicontrolled gates. The paper therefore gives context for why the kernel-map SELECT is cheap and gives no cheaper construction for it.
- [I] The IBM backend depth reductions concern general sparse index maps routed on heavy-hex; whether those depths transfer to the repo's 6-qubit circuits needs a transpilation against a named Heron r2 target: not run.
