Build a shallow GHZ circuit from one of the ranked trees over the layout.

Parameters:  
- **qubit_layout** ([*Sequence*](https://docs.python.org/3.11/library/collections.abc.html#collections.abc.Sequence "(in Python v3.11)")*\[*[*int*](https://docs.python.org/3.11/library/functions.html#int "(in Python v3.11)")*\]*) – The subset of system-qubits used in the protocol, indexed from 0.

- **backend** ([*IQMBackendBase*](https://docs.iqm.tech/4.7/iqm-client/api/iqm.qiskit_iqm.iqm_backend.IQMBackendBase.html#iqm.qiskit_iqm.iqm_backend.IQMBackendBase "(in IQM client v36.0.0)")) – The backend whose coupling map defines the connectivity.

- **num_qubits** ([*int*](https://docs.python.org/3.11/library/functions.html#int "(in Python v3.11)") *\|* *None*) – Size of the GHZ state; `None` uses every qubit of the layout. When smaller than the layout, the tree search chooses which qubits to use.

- **tree_options** ([*TreeSearchOptions*](https://docs.iqm.tech/4.7/iqm-benchmarks/api/iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions.html#iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions "iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions") *\|* *None*) – What the tree search minimizes; defaults to [`TreeSearchOptions`](https://docs.iqm.tech/4.7/iqm-benchmarks/api/iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions.html#iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions "iqm.benchmarks.entanglement.ghz_optimal.TreeSearchOptions").

- **rank** ([*int*](https://docs.python.org/3.11/library/functions.html#int "(in Python v3.11)")) – Which of the ranked candidates to build, `0` being the best-scoring one.

Returns:  
The GHZ circuit (measured), the physical qubits in logical-qubit order, and the chosen candidate (`None` for a single-qubit layout, where there is no tree to choose). Logical index `i` corresponds to the `i` th returned qubit; that order must be given to the transpiler as the initial layout, so the tree edges land on physical couplings without a layout search.
