Module: [`exa.common.data.setting_node`](https://docs.iqm.tech/4.7/iqm-exa-common/api/exa.common.data.setting_node.html#module-exa.common.data.setting_node "exa.common.data.setting_node")

Bases: [`BaseModel`](https://docs.iqm.tech/4.7/iqm-exa-common/api/exa.common.data.base_model.BaseModel.html#exa.common.data.base_model.BaseModel "exa.common.data.base_model.BaseModel")

A tree-structured [`Setting`](https://docs.iqm.tech/4.7/iqm-exa-common/api/exa.common.data.parameter.Setting.html#exa.common.data.parameter.Setting "exa.common.data.parameter.Setting") container.

Each child of the node is a [`Setting`](https://docs.iqm.tech/4.7/iqm-exa-common/api/exa.common.data.parameter.Setting.html#exa.common.data.parameter.Setting "exa.common.data.parameter.Setting"), or another [`SettingNode`](#exa.common.data.setting_node.SettingNode "exa.common.data.setting_node.SettingNode"). Iterating over the node returns all children, recursively. Settings can be accessed by dictionary syntax or attribute syntax:

```
>>> from exa.common.data.parameter import Parameter
>>> from exa.common.data.setting_node import SettingNode
>>> p1 = Parameter("voltage", "Voltage")
>>> f1 = Parameter("frequency", "Frequency")
>>> sub = SettingNode("sub", frequency=f1)
>>> settings = SettingNode('name', voltage=p1)
>>> settings.voltage.parameter is p1
True
>>> settings['voltage'].parameter is p1
True
>>> settings.voltage.value is None
True
>>> settings.voltage = 7  # updates to Setting(p1, 7)
>>> settings.voltage.value
7
>>> settings["sub.frequency"] = 8
>>> settings["sub.frequency"].value
8
```

*classmethod* fast_construct(*name*, *settings=None*, *subtrees=None*, *\**, *path=''*, *align_name=True*, *generate_paths=False*, *\*\*kwargs*)  
Fast construction alternative to \_\_init\_\_ from trusted serialized dict using model_construct.

This is the “middle ground” between `__init__` (full validation and normalization) and `BaseModel.model_construct` (no normalization).

The key purpose is performance: when loading large trees (e.g. tens of thousands of settings) that were already validated before being written to the database, re-running Pydantic validation and index construction in `__init__` is unnecessary and expensive. `fast_construct` lets us reuse that trusted data as-is and skip the extra work.

This must only be used with already validated / trusted data (DB rows, internal API payloads, etc.). It intentionally skips Pydantic validation and coercion, so untrusted input should always go through the normal constructor instead.
