## 2. Minimal operating contract

Ordered by what they protect: a secret, then an unapproved or destructive provider action, then retained data, then shared git history, then a speculation recorded as a result.

### Text that stays

1. Secrets. No token, key, account identifier, CRN, email address, or local absolute path in a commit, a log, or memory. An IBM instance is a 12-hex sha256 of its CRN. The GitHub owner and the Kaggle `owner/slug` stay in records so `collect` and `status` can resolve them.
2. Spend and publication. No hardware job, paid upload, notebook session, timeslot, or provider QRNG without the owner's written case. The case states the question, why a simulation cannot answer it, the backend, the shots, the expected seconds, and the expected credits. IBM `--submit` goes through `sh scripts/approved_run.sh`. `GOROROBA_IBM_ACCOUNT` is the same for that case's dry run, submit, and collect. Quotas do not pool. Open Quantum `prepare_job` on the public plan publishes the circuit. Free ANU and Outshift draws, calibration reads, transpilation, local noise simulation, retrieval, and `--preserve-raw` need no case.
3. Other workers. Do not cancel a job you did not submit. Cancellation requires the `job-cancellation-authority-v1` record in `docs/runbooks/evidence-closure.md`.
4. Retained data. A file a ledger or digest binds keeps its path and its bytes. A correction is a new file. `raw/<job_id>/` is never rewritten. A retained acquisition enters `docs/state/research_state.json` with a citing claim in the same change. External-only sources stay in the private documents repository.
5. Shared history. The permission harness still denies force-push and recursive delete. Merge with a merge commit. Retarget a stacked PR to main before deleting its base. Codex is the only hosted reviewer; do not request Copilot. When the Codex quota is exhausted, the owner decides.
6. Claims. A mock or `--native-dry-run` timing never enters a claim or a measured figure. New seed literals come from a draw the seed ledger accepts; a seed that reproduces a retained record keeps its value.
7. Two overrides of the user guide, one line each. The four green `pr.yml` checks admit a merge, and a local gate or premerge replay is not a push requirement. Merge commits override squash.
8. One routing line, until the launchers enforce it. At most 14 qubits go to Kaggle; 16 or more, or a question about the device, go to IBM hardware with a case that says why Aer cannot; 15 qubits wait for a case that names the substrate.

That is about 40 lines. Everything else in the 203-line text is a check, a runbook, or a deletion.

## 4. What a first-principles view sees about the CI

The owner cannot deduce the purpose because the comments and the triggers describe two different systems.

The design written down in `ci/AGENTS.md:444-484` is a three-speed ledger.

- Pull requests run the gates the diff reaches, and only those measured at 15 s or under (`pr_checks.sh:93-106`). `--affected-ledger` widens which gates count as reached. It does not skip a gate (`run_gates.py:472-476`, `515-535`).
- A push to main would run with `--ledger` and skip a gate whose key is unchanged (`run_gates.py:492`).
- The nightly runs `--ledger-audit`, which executes every gate and fails if one the ledger would have skipped now fails (`run_gates.py:494-498`, `ci.yml:152`). The text gives this a precise purpose: catch reads the tracer cannot see, and bound that miss to one day (`ci/AGENTS.md:479-484`).

The workflow that exists has the third speed only. `ci.yml` triggers on `schedule` and `workflow_dispatch` (`ci.yml:7-10`). Both select `--ledger-audit`. The `--ledger` branch is unreachable. There is no push trigger. The comment at `ci.yml:5-6` says the pull-request and push forms are kept for a later trigger. So the ledger's skip never saves a CI minute. The nightly spends the full measured sum, about 48 minutes of pr-tier gates plus about 456 minutes of full-tier gates, sharded across 12 runners, in order to police a skip that no job performs.

Three separate repeaters sit on top of that.

The pull request lints twice. Jobs `lint` and `types` run ruff and mypy. Gates `core-000`, `core-001`, and `core-002` run ruff again on the same trees when the diff reaches them. `core-039` is mypy at 51.6 s with tier `pr` (`ci/gates.json:233-235`), so the 15-second cutoff drops it and the types job is the only pull-request mypy. Ruff is the pure duplicate.

The label `pr` does not mean "runs on a pull request." Tier changes at 30 s (`ci/AGENTS.md:75-78`, `tests/ci/test_gate_inputs.py:354-356`). The pull-request cutoff is 15 s (`run_gates.py:255-256`). Fifty-one gates are tier `pr` and over 15 s, so they run only on the nightly. `core-615`, the behavioral suite, is 15.1 s (`ci/gates.json:1800-1803`), so a tenth of a second puts the audit-marked tests on the next morning's schedule. A merge can be green and wrong until 09:17 UTC. That is the hole the three drifted bindings fell through, whenever the binding's gate was over 15 s or the tracer did not connect the edit to the gate.

The nightly pages the owner for failures that qualify no claim. `ci/audit_report.py:32-38` and `55-70` list each failing gate beside the claims that cite it, and qualify only those claims. A red gate with no claim changes no scientific status and still keeps the issue "Nightly audit failing" open (`ci.yml:505-519`). Twelve of sixteen red gates on the measurement day had no claim. Eight of the last nine nightlies failed. The issue has stayed open for five days through three repair PRs, and each repair enters the Codex loop. The loop's own numbers are 312 requests for 60 merges, 91 of them on 29 PRs that produced no thread.

The premerge cache (`ci/AGENTS.md:450-460`) is the same shape of machinery for local runs: concurrent sessions share one base-tree run, under a flock. The guide tells agents not to run that path. If they obey, the cache is idle. If the user guide still tells them to run it, the two guides schedule the same work.

For one person and a few agents, the CI purpose that matches the objective is this.

On a pull request, lint once, typecheck once, run the fast tests, and replay every retained record the diff can change, including the gates now stuck between 15 s and 30 s. Once a night, replay the records and the proofs the pull request did not run, and re-run the tracer-blind class: C extensions, `stat` through a directory file descriptor, and anything that reads the wall clock. Skip a pure-Python gate whose ledger key is unchanged. Audit that skip weekly, on the gates that byte-compare a retained record, which is the class that caught the three drifted bindings. A red gate that no claim cites writes a log line. A red gate that a claim cites opens the issue, because that claim is now qualified.

The dry-run rule is the same pattern in the working tree. It is prose that causes computation and bytes, it is not a check, and its output is not a result. The nightly is a check that causes computation whose purpose was a skip-audit of a skip that is not wired up. Both can shrink without touching the four boundaries that actually protect the work: unapproved spend, leaked credentials, rewritten evidence, and a speculation entered as a claim.

`CLAUDE.md` loads only `AGENTS.md`. The 490-line CI guide stays out of the session. After the cut above, the session guide is the eight boundaries and the two user-guide overrides. The runbooks keep procedures. The jobs keep the checks.
