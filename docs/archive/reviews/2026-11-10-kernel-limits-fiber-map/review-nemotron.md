  ```
  ∑_s left[i, s] · c_s · Pl_s[j] = 0  for all i, j
  ```
  But `vr = V_r` and `left` satisfies `left · V_r = 0`. If the Plücker vectors are *exactly* `v₂(y_s) T`, then `Pl = V_r T` and the system becomes `left · diag(c) · V_r T = 0`, which holds for any `c` because `left · V_r = 0`. The code then picks *one* solution from the kernel (line 141) and solves for T on a square subsystem (lines 146-149). The residual check at line 151-154 computes `V_r T - diag(c) Pl` — this is identically zero by construction of T, **not an independent test**.

- **Critical observation**: The fit is a *construction* of T and c from the samples, not a test against an independent hypothesis. The only non-trivial checks are:
  1. `nullity == 1` (one scalar solution up to scale)
  2. `t_rank == len(v_pivots)` (T has full rank)
  3. Held-out arcs are proportional to the fit (but they come from the *same* parameter space, generated by `value(arc, index)` which is a hash of "fiber-plucker-map:{arc}:{index}")

- **Mutation that would expose this**: Permute Plücker vectors against fiber points (i.e., shuffle the `plucker` array relative to `y`). The code would:
  - Fail `nullity == 1` (the system would typically have nullity 0)
  - Or produce `t_rank < v_pivots` or `fit_exact_on_all_samples = false`
  - The held-out check would also fail because `veronese(h["y"], delta) T` would not match the shuffled `h["plucker"]`

  The code *would* report this failure (it prints the verdict). **The fit is not a test of the Veronese map; it is a decomposition of the observed Plücker vectors that happens to succeed exactly.**
