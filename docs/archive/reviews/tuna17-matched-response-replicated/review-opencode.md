# Red-team review: Tuna-17 matched-response replicated proposal (PR 998, head 7a4ff6de1, diff aa669e375..HEAD)

Scope held: read-only, no files changed, no test suite run, no provider contact. All computations below ran as short python3 scripts against the worktree; every digest and number was recomputed from the bytes on disk.

## Ranked findings

**F1. The frozen analysis has no cross-replicate job-id or shot-identity check, so a deliberately spliced duplicate replicate passes. (low severity; proved by code read)**
`gororoba_quantum/qi_replicated_response.py:199-207` — `verify_job_order` requires job ids to be ints rising strictly within one batch and checks job files against that batch's manifest, per replicate only. `gororoba_quantum/qi_records.py` `validate_run` requires unique ids and unique files within one run only. Neither layer compares job ids, batch-job ids, or shot lists across the 60 run directories. A duplicate built by copying rep-M's shots into a genuine rep-N manifest with edited ids passes every current check; honest collection cannot produce it (a verbatim directory copy carries the wrong cases.json digest and is refused).
Concrete change: in `analyze_replicated_series`, require the `3*count` job ids and the `count` batch-job ids to be globally distinct (the records already flow to the analyzer), and add one fault to `tests/scripts/test_qi_replicated_response.py::test_analysis_refuses_each_fault` duplicating one run's ids into another replicate. This must land before stage-1 data exists, because the analysis is preregistered and frozen.

**F2. The level-exactness guarantee is scoped to the normal residual model, and the doc sentence and the retained power table do not say so. (mid severity as a caveat; hypothesis about device behavior)**
`docs/design/tuna17-matched-response-replicated.md:64` states "The level is exact for every sigma" — true and proved for normal residuals (I re-derived `t = mean*sqrt(N)/s1` as exactly t_11 for every sigma and every N(s1) shaping, including cap and ceil, with no peeking: N<12 refused, stage-2 count must equal the rule's N exactly, post-cap data refused, cap stop never rejects). But the retained simulation (`scripts/qi_replicated_stein_simulation.py`) draws Gaussian residuals only, and the real per-replicate residual is a sum of four bounded frequencies plus device batch effects whose distribution is unknown — the only retained scatter estimate has 3 df (interval 0.011-0.055). Heavy-tailed batch effects would inflate the true level above 0.01 while the table shows only the normal case. The design partially discloses this (sigma interval, exchangeability marks), but the exactness sentence is model-scoped.
Concrete change: one sentence after the line-64 claim scoping exactness to the normal residual model, and optionally one added simulation row with a scaled heavy-tailed draw (e.g. student-t(3)) to bound level sensitivity.

**F3. The simulation script overwrites retained evidence by default. (low severity; proved by code read)**
`scripts/qi_replicated_stein_simulation.py:31` sets `OUT` to the committed `docs/evidence/quantum_inspire/tuna17-replicated-stein-simulation.json`, and line 71 makes `--out` default to it. Frozen seeds make a bare rerun byte-identical today, but any code or scipy change silently replaces retained evidence in place. The producer script has `--check`; this one has no guard.
Concrete change: refuse to overwrite without an explicit flag, or add a `--check` mode like the producer's.

**F4. Stage-1 approval case should restate the availability/terms/queue refresh. (process note; code read)**
`docs/notes/quantum_inspire/platform-facts.md:21-23,99-113`: queue limit 5 batches per user per backend, job limit 3600 s, and the standing selector-doc requirement to refresh availability and terms before presenting an execution approval. Twelve consecutive one-batch submissions violate nothing mechanical (each job 11.28 s; 120 s pause is a ladder step; `SUBMIT_LOCK` serializes; 0 credits consistent with retained runs), but the approval case presented to you should show the refreshed numbers.
Concrete change: include the refreshed queue/availability line in the approval request.

**F5. The lag-1 unreliability conjunction is conservative at small N. (note, not a defect; computed)**
`gororoba_quantum/qi_replicated_response.py:53,144-154`: the mark requires both `|rho| > 0.3` and `|rho| > 1.96/sqrt(N)`, so at N=12 it needs `|rho| > 0.566`. The mark is alive (rho can exceed 0.566) and the design's wording matches; no decision rests on it. Optional: state the effective threshold per N in the doc. No change required.

## Claims I could not break, and what I tried

1. **Stein rule (claim 2).** Proved the final statistic is exactly t_11 under normal residuals for every sigma and every N(s1) shaping (decomposition into stage-1 mean/SD pieces with squared weights summing to 1; cap never rejects; the `continue` verdict never tests; mid-stage-2 counts refused). Recomputed with scipy: `t_{0.995,11} = 3.1058065155392804` and shift `3.9812975678033524` are bit-exact against the module constants, `C = 0.024^2/shift^2 = 3.6339019606546454e-05` bit-exact, `required(0.038) = 40`, cap edge `sqrt(60C) = 0.04669`. Exact law at delta 0: level 0.0100000; at `|delta| = 0.024`: floor power 0.80. Independent 200k-trial Monte Carlo (unallocated draw seed 33479) reproduced the retained table: sigma 0.038, delta 0 gives undecided 0.1209 and overall reject 0.0100; delta -0.024 gives overall 0.7022, within-cap 0.7988, uncapped 0.8086 — all within MC error of the committed JSON.
2. **One-batch residual cancels batch effects (claim 1).** Proved each term pairs two regions in the same circuit execution, so batch offsets, circuit-position effects, and drift between the two witness executions cancel exactly; both selectors are read simultaneously per shot. The schedule's alternation protects the diagnostics and the exploratory block-corrected estimator, not the primary contrast.
3. **Schedule and diagnostics (claim 3).** Verified each block of 4 covers order x readout exactly once and `schedule(i) == schedule(i+4)`; odd-N handling is honest (raw uses all N; block-corrected uses complete blocks and reports `count % 4` outside); the lag-1 mark is alive and conservative.

The one splice that passes is F1 — everything else I attempted to sneak through was refused.
